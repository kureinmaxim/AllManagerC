# Установка и работа на разных платформах

Единое руководство AllManagerC по установке, настройке данных, разработке и
диагностике. Рабочий проект — AiManage-Clean. Инструкции по сборке DMG и подготовке
общего релиза находятся в [BUILD_MACOS.md](BUILD_MACOS.md).

## Как запускается приложение

AllManagerC — настольное приложение с интерфейсом PyWebView и локальным сервером
Flask. `run_app.py` и `app.py` запускают GUI. Сервер слушает `127.0.0.1` и выбирает
свободный порт автоматически; фиксированный порт 5050 не требуется.

Проверенное окружение macOS: Apple Silicon arm64, macOS 26.6.2, Python 3.13.9.
Windows собирается отдельно на Windows. Запуск на Linux требует графического
окружения и подходящего движка PyWebView; в текущем объединении он не проверялся.

## Установка готового приложения

### macOS

Откройте DMG и перетащите AllManagerC в Applications. Подробности о локальной
подписи, проверке образа и сборке — в [BUILD_MACOS.md](BUILD_MACOS.md).

### Windows

Запустите Windows-инсталлятор из папки `dist\latest`. Инсталлятор создаёт ярлык в меню Пуск и, по желанию, на рабочем столе.

## Сборка Windows

Полная инструкция находится в [BUILD_WINDOWS.md](BUILD_WINDOWS.md).

Сборка Windows устроена так же, как macOS-сборка: версия берётся автоматически из `config.json`, а папка результата получает имя с версией и временем. Ручное редактирование `AllManagerC.iss` и ручной ввод имени установщика не нужны.

Однократно установите Python, зависимости и [Inno Setup 6](https://jrsoftware.org/isinfo.php):

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Проверка версии и инструментов:

```powershell
.\.venv\Scripts\python.exe build_windows.py --check
```

Полная сборка приложения и установщика:

```powershell
.\.venv\Scripts\python.exe build_windows.py
```

Результат появится в `dist\AllManagerC-<версия>-windows-<дата-время>`. `dist\latest` всегда содержит копию последней успешной сборки. В папке результата находятся папка приложения, `AllManagerC_Installer_v<версия>.exe` и `build-info.json`.

Старые результаты можно убрать, сохранив последнюю сборку:

```powershell
.\.venv\Scripts\python.exe build_windows.py --clean
```

Для полной очистки всех Windows-артефактов:

```powershell
.\.venv\Scripts\python.exe build_windows.py --clean-all
```

Перед новым релизом обновите версию из корня проекта и проверьте синхронизацию:

```powershell
py -3 scripts/version.py bump patch
py -3 scripts/version.py check
.\.venv\Scripts\python.exe build_windows.py
```

Если Inno Setup установлен не в стандартный каталог, задайте путь к компилятору:

```powershell
$env:ISCC = 'D:\Tools\Inno Setup 6\ISCC.exe'
.\.venv\Scripts\python.exe build_windows.py
```


## Запуск из исходного кода

Если проект уже находится в AiManage-Clean, используйте эту папку.
Для новой рабочей копии:

```bash
git clone https://github.com/kureinmaxim/AllManagerC.git
cd AllManagerC
```

### macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install Flask requests python-dotenv cryptography Werkzeug Jinja2 pywebview yubico-client
.venv/bin/python run_app.py
```

На macOS используется Cocoa/WebKit; дополнение Qt не требуется.
Зависимости для упаковки добавляются отдельно по BUILD_MACOS.md.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_app.py
```

### Linux с графическим окружением

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_app.py
```

Могут потребоваться системные библиотеки выбранного GUI-движка. Это не инструкция
для запуска на сервере без графической сессии.

## Виртуальные окружения и переход между ОС

Создавайте окружение на той машине, где запускается приложение. Не переносите
`.venv` между Windows, macOS и Linux: пути к Python, бинарные расширения и
системные зависимости различаются. После обновления системного Python старое
окружение тоже может перестать запускаться.

Команды выше вызывают Python напрямую, поэтому активация не обязательна.
Для интерактивной работы можно активировать окружение:

- macOS/Linux, Bash или Zsh: `source .venv/bin/activate`.
- Windows PowerShell: `.\.venv\Scripts\Activate.ps1`.
- Windows CMD: `.venv\Scripts\activate.bat`.
- Выход из активного окружения: `deactivate`.

При переходе на другую ОС получите исходники через Git и создайте собственное
окружение. Если папка `.venv` занята несовместимым окружением, создайте новое под
другим именем, например `.venv-macos`. Удалять прежнее окружение для этого не нужно.
Сборка macOS позволяет указать интерпретатор:

```bash
BUILD_PYTHON=.venv-macos/bin/python bash build_macos.sh
```

Скрипт сборки не удаляет и не пересоздаёт окружения автоматически.

## Настройки и данные

В режиме разработки `.env`, `config.json`, `yubikey_config.json`, `data`, `uploads`
и `logs` находятся в рабочей папке проекта. `run_app.py` устанавливает её сам.
При запуске `app.py` напрямую сначала перейдите в корень проекта.

Готовое приложение использует пользовательскую папку:

- macOS: `~/Library/Application Support/AllManagerC`.
- Windows: `%APPDATA%\AllManagerC`.
- Linux: `~/.local/share/AllManagerC`.

Для изолированной проверки упакованного приложения можно задать
`ALLMANAGERC_DATA_DIR` с путём к отдельной папке. Пример для macOS есть в
BUILD_MACOS.md. Обычная установка не требует этой переменной.

### Ключи и вход

`SECRET_KEY` — ключ Fernet для шифрования данных. Если ключ отсутствует, приложение
создаёт его и сохраняет в `.env`. Существующую базу нужно открывать с её исходным
ключом; генерация другого ключа не восстановит доступ к ней.

`FLASK_SECRET_KEY` — отдельный секрет сессии Flask. При ручной настройке используйте
случайное значение, например результат следующей команды, выполненной Python
нужного окружения:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

YubiKey настраивается в интерфейсе приложения. При использовании статических
паролей задайте собственные значения `YUBIKEY_STATIC_PASSWORDS` в `.env`.
Не используйте демонстрационные пароли из старых инструкций.

Переменные `DATABASE_URL`, `ENCRYPTION_KEY_FILE`, `LOG_LEVEL` и `LOG_FILE` из
прежнего руководства не являются настройками текущей реализации. Данные хранятся
в зашифрованных файлах, а не в SQL-базе. Шаблон `.env.example` в проекте отсутствует;
команда его копирования не нужна.

### Резервное копирование и перенос

Закройте приложение и сохраните вместе `.env`, конфигурации, `data` и `uploads`.
Ключ и база должны соответствовать друг другу. Через настройки приложения также
можно экспортировать пакет данных и импортировать базу с внешним ключом.

Базы исходных AiManage и AiManage-Clean сохранены отдельно. Их объединение и выбор
рабочей базы отложены пользователем. Подробности и расположение резервных копий —
в [описании объединения](docs/UNIFICATION.md). Не заменяйте ключ действующей базы
ключом из другого проекта.

## Проверки и сборка

Из нужного окружения:

```bash
python -m unittest discover -s tests -v
python check_env.py
```

Тесты используют временные каталоги и синтетические данные. `check_env.py` помогает
проверить платформу, Python, окружение и зависимости; его общие рекомендации
сверяйте с актуальными инструкциями сборки.

macOS: [BUILD_MACOS.md](BUILD_MACOS.md).
Windows PowerShell после установки инструментов сборки:

```powershell
python build_windows.py
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" AllManagerC.iss
```

Оператор `&` запускает программу по пути с пробелами. Обе платформы одного релиза
собирайте из одного коммита. Правила тегов, pre-release, загрузки файлов и SHA256
описаны в BUILD_MACOS.md.

## Диагностика

### Python или pip не найден

На macOS/Linux проверьте `.venv/bin/python`, на Windows —
`.venv\Scripts\python.exe`. Само наличие файла ещё не подтверждает исправность
окружения: запустите его с `--version`. Если отсутствует только pip:

```bash
python -m ensurepip --upgrade
```

Используйте Python нужного окружения. Если оно несовместимо с текущей системой,
создайте новое и установите зависимости заново.

### Ошибка импорта модуля

Убедитесь, что установка пакетов и запуск выполняются одним интерпретатором.
Используйте `python -m pip`, затем повторите установку зависимостей для своей ОС.
Не заменяйте общий requirements.txt полным `pip freeze` одной платформы:
туда могут попасть специфичные для неё пакеты.

### Ошибка чтения базы

Проверьте существование активного файла и соответствие ключа. При переносе старого
абсолютного пути приложение ищет файл с тем же именем в локальной папке `data`.
Если активная база отсутствует, приложение может создать пустую — это не означает,
что старая база восстановлена. Сначала сохраните исходные файлы и ключи.

### Ошибка доступа к файлам или запуска GUI

Проверьте доступ на запись к пользовательской папке данных и наличие графической
сессии. Не запускайте приложение от администратора для обхода ошибки.
Для диагностики запускайте его из терминала и смотрите вывод.

Лог безопасности находится в `logs/security.log` внутри папки данных. В режиме
разработки на macOS/Linux:

```bash
tail -f logs/security.log
```

Отдельный `logs/app.log` автоматически не создаётся. Ошибки запуска выводятся в
терминал. Сервер выбирает свободный порт; завершать чужой процесс на 5050 не нужно.

## Git и публикация

Перед коммитом проверьте `git status`, diff и исключения для окружений, ключей,
баз, загрузок и резервных копий. Проверить, отслеживается ли окружение:

```bash
git ls-files .venv venv
```

`.gitignore` не исключает уже отслеживаемые файлы автоматически. Если окружение
попало в индекс, после проверки его можно убрать из индекса без удаления с диска
командой `git rm -r --cached .venv`.

## Серверы, Docker и облако

Прежнее руководство содержало общие примеры Nginx, Gunicorn, Supervisor, systemd,
Docker, Heroku и EC2. Они не соответствуют текущему настольному запуску: GUI требует
графической сессии, порт выбирается динамически, данные хранятся в локальных файлах.
Поэтому эти примеры не включены как готовые команды развёртывания.

Для серверной версии потребуется отдельный режим запуска без GUI, продуманная
аутентификация, HTTPS, постоянное хранилище и проверка конкурентной записи данных.
Текущая локальная сборка такого режима не заявляет.
