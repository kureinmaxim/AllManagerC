## 📋 Проблема 1: Повреждение данных и ошибки ID сервисов

### Симптомы
- Потеря данных: все сервисы исчезали после добавления нового.
- Ошибка "Неверный ID сервиса" при попытке редактирования или удаления.
- Ошибка 500 (Internal Server Error) на странице добавления сервиса.

### Диагностика и причины
1.  **Повреждение файла данных**: Активный файл данных периодически повреждался, урезаясь до 100 байт.
2.  **Несоответствие типов ID**: Новые сервисы создавались с текстовым ID (`uuid`), в то время как функции редактирования/удаления ожидали числовой ID (`int`).

### 🛠️ Решение
1.  **Восстановление данных**: Данные были восстановлены из автоматически созданных резервных копий.
2.  **Исправление генерации ID**: Алгоритм генерации ID был изменен на `max(existing_ids) + 1`, что обеспечивает уникальные числовые ID.
3.  **Созданы утилиты**: Разработаны скрипты для диагностики (`data_integrity.py`) и восстановления (`fix_data_integrity.py`) данных.

## 📋 Проблема 2: Ошибка 500 в собранном приложении (macOS)

### Симптомы
- Internal Server Error при взаимодействии с YubiKey или при открытии страниц редактирования сервисов *только в собранном `.app` файле*. В режиме разработки все работало.

### Диагностика и причины
- **Файл схемы не найден**: Сборщик `PyInstaller` не включал файл `ai_services_schema.json` в финальный пакет. Приложение не могло найти схему и падало с ошибкой.

### 🛠️ Решение
1.  **Встроенная схема**: В код была добавлена "запасная" схема данных по умолчанию.
2.  **Улучшенная обработка ошибок**: Приложение теперь не падает, если файл схемы не найден, а использует встроенную схему и выводит предупреждение в лог.
