# Аутентификация AllManagerC

Защита предназначена для локального приложения и не делает Flask-сервер безопасным
для публикации в сети.

## Способы входа

| Способ | Интернет | Источник | Назначение |
|---|---:|---|---|
| YubiKey OTP | Да | Client ID, Secret Key, одноразовый OTP | Онлайн-вход |
| Статический пароль | Нет | `YUBIKEY_STATIC_PASSWORDS` | Офлайн-резерв |
| Secret PIN | Нет | окружение или конфиг | Локальный резерв |

После успеха устанавливается `session['yubikey_authenticated'] = True`; cookie
сессии называется `allmanagerc_session`.

## Проверка запроса

1. Проверяется локальный IP.
2. При выключенной защите запрос пропускается.
3. При включённой защите проверяется сессия.
4. Без сессии разрешены вход, статика, справка и служебные маршруты.
5. Остальные запросы перенаправляются на `/yubikey/login`.

Если ключей и статических паролей нет, включённая защита направляет остальные URL
на `/yubikey/setup`.

## Статические пароли

В `.env` профиля приложения задайте собственные значения:

```env
YUBIKEY_STATIC_PASSWORDS=длинный-пароль-1,другой-длинный-пароль
```

Значения разделяются запятыми и сравниваются как строки. Это повторно используемые
секреты, не одноразовые OTP; они хранятся в окружении открытым текстом. После
изменения перезапустите приложение. Не добавляйте `.env` в Git.

## YubiKey OTP

Получите Client ID и Secret Key в Yubico, войдите доступным способом, откройте
настройку YubiKey, добавьте ключ и включите защиту. При онлайн-входе приложение
проверяет связь, отправляет OTP в YubiCloud и обрабатывает `OK`, `BAD_OTP`,
`REPLAYED_OTP`, `NO_SUCH_CLIENT` и `BAD_SIGNATURE`.

Ограничить вход конкретными ключами можно так:

```env
YUBIKEY_ALLOWED_PUBLIC_IDS=cccccbgklrhh,aaaaaabbbbbb
```

Также поддерживается `allowed_public_ids` в `yubikey_config.json`. При пустом списке
первый успешный online OTP может автоматически привязать public ID. Secret Key Yubico
хранится открытым текстом в конфигурации, поэтому ограничьте права профиля ОС.

## Secret PIN

Источник PIN выбирается в порядке: `DEV_PIN`, `DEVELOPER_PIN`,
`config.json → security.secret_pin.current_pin`, `security.dev_pin`, затем резервное
значение `1234`. PIN хранится открытым текстом. После трёх неверных попыток
`/secret/login` блокируется на 30 секунд; счётчик сбрасывается при перезапуске.

Отдельный `/dev_login` использует собственную логику и переменные окружения. Смена
Secret PIN не гарантирует изменение developer-входа.

## Отключение и восстановление

Резервная копия нужна до ручного изменения `.env`, `config.json` или
`yubikey_config.json`. Минимальная конфигурация отключённой защиты:

```json
{"keys": [], "enabled": false}
```

Если доступ потерян, закройте приложение, сохраните профиль и базу, проверьте
исходный `SECRET_KEY`, затем импортируйте копию с внешним ключом. Простая замена
ключа не расшифрует старую базу.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Статические пароли не настроены | `YUBIKEY_STATIC_PASSWORDS` в `.env` нужного профиля |
| YubiKey отклонён | `enabled`, Client ID, Secret Key, сеть и статус Yubico |
| Public ID запрещён | Список разрешённых ID и используемый ключ |
| Редирект на setup | Нет ключа и статического пароля при включённой защите |
| PIN не меняется | `DEV_PIN` и `DEVELOPER_PIN` имеют приоритет |
| После переноса нет данных | `.env` и `.enc` должны быть из одной установки |

Журнал находится в `logs/security.log`. Он не является полным аудитом и не
гарантирует маскирование всех чувствительных сведений.

## Ограничения

- Резервное значение PIN `1234` остаётся доступным без переопределения.
- Полный экспорт содержит ключ Fernet и не защищён отдельным паролем.
- Общей CSRF-защиты форм нет; некоторые служебные маршруты разрешены без входа.
- Локальный порт и cookie не заменяют авторизацию.
- YubiKey не хранит ключ Fernet; профиль ОС всё равно нужно защищать.

Полный список рисков находится в [SECURITY.md](SECURITY.md).
